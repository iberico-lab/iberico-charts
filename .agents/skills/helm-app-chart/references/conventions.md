# Design rules for the charts

Follow these when changing anything under `charts/`. They're why the chart is
easy to use, so a change that breaks one needs a very good reason.

## 1. Every setting has a working default

A values file with only an image must produce a running app. New features are
**off** (or harmless) by default. Defaults live in `charts/app/values.yaml`,
each with a one-line comment.

## 2. Set one field, keep the rest

Helm merges user values over the defaults **per map key**. So:

- Declare nested defaults as full maps (see the probe blocks), so changing one
  field is safe.
- Lists replace the default. Keep list defaults empty (`[]`).
- To let users remove a default, honour `null` (Helm drops the key).

## 3. Fail loudly, with the fix in the message

Never render something broken or silently ignore a value. Two layers:

- **Schema** (`values.schema.json`, generated by `hack/gen-values-schema.py`,
  `additionalProperties: false`) catches typos, wrong types and bad enums.
- **Template `fail`** catches cross-field mistakes the schema can't, e.g.
  `ReadWriteOnce` with several Deployment pods, `minAvailable >= replicas`, HPA
  without a CPU request, duplicate container names, a dotted Tailscale
  hostname, a `public-sso` URL without a login middleware.

A message names the setting, what's wrong, and what to do, e.g.
`persistence "data" is ReadWriteOnce, so only one pod can use it, but this
Deployment runs several pods: use replicas: 1, a ReadWriteMany storage class,
or workload.type: StatefulSet`.
Add each new message to `docs/troubleshooting.md`.

## 4. Upgrades must keep working

- Selectors (`helm-helpers.selectorLabels`: name + instance) never change. Never
  add version or chart labels to selectors, to `volumeClaimTemplates`, or to
  anything else Kubernetes won't let you change later.
- Pods that aren't app pods (e.g. the `helm test` pod) must **not** carry
  `app.kubernetes.io/name`, or Services and PDBs select them.
- Renaming or removing a setting is a breaking change: say so in `CHANGELOG.md`,
  and keep upgrades working (see rule 4).

## 5. Names

- `helm-helpers.fullname`: `global.fullnameOverride`, else `global.name`, else the
  release name. Validated as a DNS name (max 63).
- Derived names add a suffix: `<app>-cluster` (headless), `<app>-files`
  (configFiles), `<app>-onepassword-env` / `-files`.

## 6. One pod template

Deployments and StatefulSets share `app.podTemplate` (`templates/_pod.yaml`).
Pod-level features go there once, never in one workload type only.

## 7. Raw passthrough where users know Kubernetes

`extraContainers`, `extraInitContainers`, `extraEnv`, `extraEnvFrom`,
`lifecycle`, `affinity`, `tolerations`, `topologySpreadConstraints`,
`autoscaling.behavior` and `extraManifests` are copied as-is (`extraManifests`
through `tpl`). Structured settings exist only where the chart adds value
(defaults, validation, wiring).

## 8. Plain-language docs

Every setting appears in `docs/` (`make docs-check` enforces it). Pages follow
the same layout: a one-line summary, a copy-paste snippet, "Gotchas", a
settings table, "Next". Short sentences, no emojis.

## Checklist for a change

- [ ] Default in `values.yaml` with a comment; key in `hack/gen-values-schema.py`; `make schema`
- [ ] Unit test in `charts/*/tests` (happy path and each `fail`)
- [ ] Docs: the feature page, `docs/values-reference.md`, troubleshooting for new errors
- [ ] `CHANGELOG.md`, with a `### Breaking` section if anyone has to act
- [ ] `make docs-check test validate examples` pass; `make e2e` for anything pod-level
